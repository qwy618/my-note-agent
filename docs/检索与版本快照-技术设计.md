# 笔记管家 · 检索升级 + 版本快照 技术设计

> 目标：消除日常使用最「卡」的两处 —— 笔记多了找不到、管家改文件怕丢。
> 本文档先方案后落地，落地顺序：**先检索（阶段 A），再版本快照（阶段 B）**。

---

## 0. 背景与目标

当前笔记管家已具备读/写/编辑/拖拽上传/PDF/Word/Excel/OCR/配图提取/两遍式笔记/记忆/定时/标签/双向链接/导出 HTML。骨架完整，但有两处影响日常使用的短板：

| 短板 | 现状 | 目标 |
|---|---|---|
| 检索 | 已有全文搜索，但**无索引、无排序、无高亮、无语义** | 快、准、看得见命中在哪 |
| 版本安全 | 写文件**直接覆盖**，无历史 | 任意历史版本可回滚，防丢数据 |

---

## 1. 现状盘点（基于真实代码）

### 1.1 检索现有能力

- **前端**：`static/index.html` 已有 `#searchInput`（多词空格分隔、300ms 防抖）+ `#searchResults` 结果面板；另有类型/标签/状态筛选（`curType/curTag/curStatus`）、标签聚合页、双向链接。
- **后端**：`server.py` 提供 `GET /api/search?q=` → `agent.search_notes(q)`（`agent.py:286`）；另有 `GET /api/notes`（列表）、`GET /api/notes/meta`（仪表盘元数据）。

### 1.2 `search_notes` 的四个缺口（`agent.py:286-305`）

```python
for p in sorted(NOTES.rglob("*")):                  # ① 无索引：每次全量遍历所有文件
    if not p.is_file() or p.suffix.lower() not in TEXT_EXTS: continue
    lines = p.read_text(encoding="utf-8").splitlines()
    for i, line in enumerate(lines, 1):
        if all(k in line.lower() for k in keywords):   # ② AND 过严：一行必须命中全部词
            hits.append({"file": rel, "line": i, "snippet": line.strip()[:80]})
            if len(hits) >= max_results: return hits    # ③ 无排序：先到先得，满即停，可能漏更相关命中
```

- **① 无索引**：每查一次遍历全部文件×逐行，笔记量上来后 O(文件数×行数)，卡。
- **② AND 语义过严**：多词时要求**同一行**命中全部关键词，跨段/跨行命中不到（如「Spring 集成 MyBatis」两个词分布在不同小节）。
- **③ 无相关性排序**：命中只是顺序收集，满 `max_results` 就返回，可能漏掉更相关的。
- **④ 无高亮 / 无上下文**：`snippet` 只取该行前 80 字符，前端无法标记命中词，也看不到前后文。
- **⑤ 无语义**：纯子串匹配，同义词/模糊语义找不到（搜「唤醒词」找不到写「小智小智」的段落）。

### 1.3 版本安全现状

- 所有写文件工具（`write_note` / `edit_note` / 前端拖拽生成的 `build_note` 落盘等）都是 `path.write_text(...)` **直接覆盖**，无任何历史。
- 无 `.history` 目录、无 git、无回滚入口。

## 2. 检索子系统升级（阶段 A）

### 2.1 设计原则

- **保留现有能力**：不动已有搜索框入口、筛选、标签聚合；只把「后端匹配 + 结果呈现」升级。
- **两阶段渐进**：阶段 A1 做「索引 + 排序 + 高亮」低成本高收益；阶段 A2（P1，可选）做语义检索，不阻塞。

### 2.2 数据模型：内存倒排索引

在 `agent.py` 增加一个索引模块，构建「词 → 出现位置」倒排表，供搜索加速 + 排序：

```python
# 内存倒排索引（可序列化到 .state/index.json 持久化）
Index = {
  "doc_count": 12,
  "terms": {                       # word.lower() -> 位置列表
    "spring":  [ {"file":"第3章 Spring Bean.md","lines":[3,17,42], "in_title":True}, ... ],
    "mybatis": [ ... ],
  }
}
```

- **词切分**：中文按 2-gram（bigram）切（如「集成」→「集成」），英文/数字按 `[a-z0-9]+` 切；建表时对每行做同样切分。
- **构建时机**：进程启动时 `rebuild_index()` 全量建一次；每次写/改文件后 `update_index(path)` 增量更新该文件对应词条。
- **持久化**（可选）：写 `.state/index.json` 供重启秒载；不持久化则启动重建（笔记量 < 100 时重建 <1s，可接受）。

### 2.3 匹配与评分（重写 `search_notes`）

把「一行 AND」改为「文档级 OR + 加权评分」，返回带分值的结构化结果：

```python
def search_notes(query, max_results=20):
    words = tokenize(query)
    scores = {}                       # file -> (score, hit_lines, in_title)
    for w in words:
        for pos in index.lookup(w):
            s = scores.setdefault(pos["file"], [0, [], False])
            s[0] += 3 if pos["in_title"] else 1        # 标题命中加权
            s[1].extend(pos["lines"])
    # 排序：命中词数多、命中位置靠前、标题命中者优先
    ranked = sorted(scores.items(),
                    key=lambda kv: (-score, -min(lines), file))
    return [build_hit(file, lines, words) for file, _ in ranked[:max_results]]
```

关键行为变化：
- **OR + 计数**：命中一个词即入选，命中越多分越高（宽松但精准排前）。
- **标题加权**：命中标题的词加权 3，优先返回。
- **多关键词**：不再要求同行，跨段/跨行命中也能找到。

### 2.4 返回结构与高亮

每个 hit 返回**上下文 + 高亮标记**，前端据此渲染：

```json
{
  "file": "第3章 Spring Bean.md",
  "title": "Spring Bean 生命周期",
  "score": 4,
  "snippet": "Bean 生命周期包含 <mark>实例化</mark>、<mark>初始化</mark>、销毁三阶段",
  "line": 17,
  "lines_before": ["...上两行..."],
  "lines_after": ["...下两行..."]
}
```

- 后端在 snippet 中把命中词包进 `<mark>`（或返回 offset，前端高亮）。
- `lines_before/after` 给命中行前后 1-2 行上下文，避免「只见一行」。

### 2.5 API（向后兼容扩展）

```text
GET /api/search?q=<query>
# 返回 { "query": "...", "count": n, "results": [ {file,title,score,line,snippet,lines_before,lines_after} ] }
```

- `results` 字段名保持 `results`（前端 `d.results` 已用，见 `doSearch`），**只增字段不改名**，前端旧逻辑兼容。
- 新增 `GET /api/index/status` → `{doc_count, term_count, build_ms}`（诊断用，可选）。

### 2.6 前端增强（`doSearch` 改造）

- 结果项渲染：标题（可点击开笔记弹层）+ 命中上下文（`<mark>` 高亮命中词）+ 文件路径/行号。
- 空结果态：提示「未找到，可试试少用一个词 / 换个说法」。
- 保留 debounce 与 `#searchResults` 面板，样式沿用现有瑞士网格（直角、teal 高亮 `<mark>`）。

### 2.7 语义检索（阶段 A2，P1 可选）

- **取舍**：
  - **本地嵌入**（`sentence-transformers` + 中文 bge-small-zh）：免费、离线、隐私；代价是装依赖（~几百 MB 模型）占内存。
  - **API 嵌入**（如 deepseek/其他 embedding 端点）：质量高、零本地依赖；代价是联网 + 要 key + 每次查询有延迟与成本。
- **建议**：阶段 A1 关键词升级已解决 90% 痛点，**语义检索不阻塞交付**；待阶段 A1 稳定后再评估是否引入，默认走本地 bge-small 离线方案。

## 3. 版本快照子系统（阶段 B）

### 3.1 目标与选型

- 目标：任何一次写文件前，自动保留旧内容；任意历史版本可查看、回滚；防误改/误删。
- **选型：文件快照，不引 git**（git 强但引入仓库/提交语义/分支复杂度，与「单文件本地 agent」定位不符）。文档记录：若未来要团队协作或多设备同步，再切换 git。

### 3.2 存储结构

```
notes/
  .history/                       # 快照目录（建在 notes 内，搜索/导出时排除）
    第3章 Spring Bean.md__20261003_195500.bak
    第3章 Spring Bean.md__20261003_200112.bak
    ...
  manifest.json                   # 快照索引：{ file -> [ {ts, size} ] }，可选，用于快速列出
```

- 文件名：`<原文件名>__<YYYYmmdd_HHMMSS>.bak`（同一文件多次覆盖产生多份，按时间戳区分）。
- **保留策略**：每个文件最多保留最近 `K=20` 份（可配置），超限删除最旧，防快照无限膨胀。

### 3.3 触发时机（写前钩子）

所有落盘入口统一加「写前快照」：

```python
def snapshot_before_write(relpath: str):
    src = NOTES / relpath
    if not src.is_file(): return            # 新建文件无需快照（旧内容不存在）
    dst = HISTORY / f"{src.name}__{now_str()}.bak"
    shutil.copy2(src, dst)
    prune(relpath, keep=20)                # 保留策略
```

接入点（`agent.py`）：
- `write_note` / `edit_note`（工具层）
- 前端拖拽/导入生成的笔记落盘处（`build_note` 相关写文件逻辑）
- 记忆文件写入（`.memory/` 可选，若也要防丢）

### 3.4 后端 API

```text
GET  /api/history?file=<relpath>            # 列某文件的快照列表 [{ts, size, path}]
GET  /api/history/content?file=<relpath>&ts=<ts>   # 取某版本全文（预览）
POST /api/history/restore                   # body {file, ts} → 用该版本覆盖当前文件
DELETE /api/history?file=<relpath>&ts=<ts>  # 删除单份快照
DELETE /api/history?file=<relpath>          # 清空某文件全部快照
```

实现要点（`server.py` + `agent.py`）：
- 列/取/回滚均限定在 `notes/.history` 内，沿用现有 `is_relative_to` 越界校验，防逃逸。
- `restore` 本质：`shutil.copy2(快照, 当前文件)`，回滚**之前**先对当前内容再快照一份（保留操作轨迹，误回滚也能再滚回）。

### 3.5 前端（笔记弹层的「历史版本」面板）

- 在打开笔记的详情弹层顶部加「历史版本」入口（徽标显示快照数）。
- 面板：时间倒序列表（`10-03 19:55 · 8KB`）→ 点击加载 `content` 预览（只读渲染）→ 「回滚到该版本」按钮（二次确认）。
- 样式沿用瑞士网格；与定时任务卡片面板同构（列表 + 操作），体验一致。

## 4. 实施步骤

### 阶段 A · 检索升级
1. `agent.py`：新增索引模块（`tokenize` / `rebuild_index` / `update_index`）+ 重写 `search_notes`（OR + 评分 + 上下文 + `<mark>`）。
2. 写/改文件工具末尾调 `update_index(path)`。
3. `server.py`：扩展 `/api/search` 返回新字段（不改 `results` 名）。
4. `static/index.html`：改 `doSearch` 渲染高亮 + 排序结果 + 空态。
5. **验收**：中文 bigram / 多词跨行 / 标题命中加权 / 性能（100 篇量级 <100ms）。

### 阶段 B · 版本快照
1. `agent.py`：`HISTORY` 目录 + `snapshot_before_write` + `prune` + 列/取/回滚/删函数。
2. 接入所有写文件入口（`write_note`/`edit_note`/导入落盘）。
3. `server.py`：4 个 `/api/history` 端点（含越界校验 + restore 先快照）。
4. `static/index.html`：笔记弹层「历史版本」面板。
5. **验收**：编辑 → 列快照 → 预览旧版 → 回滚 → 内容恢复；超限清理生效。

## 5. 决策点（待确认）

| 决策 | 选项 | 倾向 |
|---|---|---|
| 索引持久化 | 内存重建 / `.state/index.json` 落盘 | 先内存重建（量小够快），量大再落盘 |
| 快照保留份数 | 每文件 10 / 20 / 30 | 20（默认） |
| 语义检索 | 本地 bge / API 嵌入 / 暂不做 | 阶段 A1 先不做，稳定后再评估本地 bge |
| 记忆文件是否也快照 | 是 / 否 | 是（成本极低，防偏好丢失） |
| 快照目录是否纳入搜索/导出 | 排除 / 纳入 | 排除（`.history` 不参与 `search_notes` 与导出 HTML） |

## 6. 验收标准（合订）

- 检索：搜「Spring 集成 MyBatis」能跨行命中并高亮；标题命中排前；100 篇笔记查询 <100ms；结果可点击打开笔记。
- 版本：写文件自动留快照；面板可预览任意历史版；回滚后内容正确恢复、且回滚操作本身也留快照；`.history` 不污染搜索结果与导出。
