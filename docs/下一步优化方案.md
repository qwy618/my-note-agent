# 笔记管家・下一步优化方案（v2）

> 定位：把「能用的学习管家」打磨成「真正每天愿意打开、离不开的学习管家」。
> 依据：README（M0–M7 已实现）+《检索与版本快照 - 技术设计》（A1 关键词检索、B 版本快照均已落地）。
> 原则：先补稳定性与可见性（真实痛点），再长学习能力（定位纵深），最后积累数据资产。每一项都标了痛点 / 方案 / 工作量 / 验收。



***

## 0. 一句话现状

**骨架完整**：读 / 写 / 改、生产级两遍式笔记、配图提取、全文检索（A1）、版本快照（B）、记忆、定时、后台、子 agent、多格式拖入 + OCR、导出 HTML、标签 / 筛选 / 双向链接、瑞士网格 UI—— 日常闭环已经能跑。

**但有两个真实短板没解决**（正是今天暴露的）：定时 / 后台任务**执行结果对用户不可见**、失败无痕；生成链路仍依赖不稳定的 LLM 空返回（已做部分兜底）。



***

## 1. 第一梯队（P0）・稳定性与可见性 —— 最该先做

### 1.1 定时 / 后台任务「执行结果可见化」 ⭐ 强烈推荐先做



* **痛点（今天实测暴露）**：你 12:10 发的定时任务，触发成功（`.outputs/scheduler.log` 有 `[12:10:00] sch3 触发`），但后台执行因 `slice indices must be integers` 抛异常失败 → 任务被移除（你看到 "消失"）+ 没生成笔记，而你完全不知道失败、失败原因也无处可查。

* **现状**：`TaskManager` 只把 `status/result/error` 放在内存对象里（`/api/bg` 能查到，但**没落盘、前端没暴露**）；调度日志只记 "触发"，不记 "结果"。

* **方案**：


  * `TaskManager` 每次任务结束后，把 `{tid, kind, prompt摘要, status, 产出文件名, error, 触发时间, 结束时间}` 追加写 `.state/tasks.json`（保留最近 N=50 条）。

  * 定时任务面板：每个任务卡片显示**上次执行状态**（成功・产出文件名 / 失败・原因），失败可一键「重跑」（重新 `schedule_at` 或直接重放 prompt）。

  * 失败原因沿用已加的完整 traceback。

* **工作量**：后端 1 个落盘函数 + 1 个列表接口 + 前端任务卡片加一栏状态。约 0.5 天。

* **验收**：故意造一次失败任务 → 面板显示失败原因 → 点重跑 → 成功产出笔记；重启后历史执行记录仍在。

### 1.2 定时任务的「确定性优先」执行



* **痛点**：定时任务把裸 prompt 丢给子 agent 自主执行，是否落盘笔记**取决于大模型判断**，且 deepseek 空返回是常态（热点分组就是它空返回导致 "全是其他"）。

* **方案**：给热点 / 天气 / 新闻这类 "产出固定结构笔记" 的任务，建立**确定性工具路径**（如 `hot_notes`），定时触发时优先走工具直写，LLM 只做可选增强；失败自动重试 2 次再标记失败。

* **验收**：定时热点任务 100% 产出笔记文件（不再 "触发了但没笔记"）。

## 2. 第二梯队（P1）・检索与问答 —— 把「学习管家」立起来

### 2.1 语义检索（承接《技术设计》阶段 A2，P1 可选）



* **现状**：A1 关键词检索（索引 + 排序 + 高亮）已落地，解决 "找得到"。

* **缺口**：纯子串匹配，同义词 / 口语查不到（搜 "唤醒词" 找不到写 "小智小智" 的段落）。

* **方案**：本地 `sentence-transformers` + 中文 `bge-small-zh`（免费、离线、隐私），A1 命中不足时用向量召回补齐；默认本地离线，不引入 API。

* **工作量**：装依赖 + 索引构建 + 融合排序。约 1 天。

* **验收**：搜口语 / 同义表达能命中语义相关笔记，且关键词命中仍排前面。

### 2.2 跨笔记问答（RAG） ⭐ 定位纵深



* **痛点**：管家答 "单个笔记" 很稳，但答 "跨几篇综合题"（如 "我 Spring 和 MyBatis 的笔记里，事务相关都讲了什么"）做不到。

* **方案**：复用已有倒排索引（A1）选 Top-K 相关笔记 → 拼成上下文块（带文件名锚点）→ 喂给大模型作答，**答案末尾列引用来源（笔记名 + 小节）**。本质就是轻量 RAG，不引入向量库也能做（关键词召回够用）。

* **工作量**：1 个 `ask_notes(query)` 工具 + 前端 "问全库" 入口。约 0.5 天。

* **验收**：问跨文问题能给出带引用来源的综合回答，可点来源跳转到对应笔记。



***

## 3. 第三梯队（P2）・学习闭环 —— 对抗遗忘

### 3.1 每日回顾 / 复习（学习管家核心价值）



* **方案**：定时任务 "每天 21:00" 自动生成本日小结笔记（今天新增 / 修改了哪几篇 + 每篇一句话结论）+ 随机抽 1–3 篇旧笔记做 "闪卡式回顾"（抽关键结论、标注上次复习日期）。配合已有记忆，形成 "记录 → 检索 → 复习" 闭环。

* **工作量**：1 个 `daily_review` 确定性工具。约 0.5 天。

### 3.2 生成本篇自测题



* 你已在做 "易错题"（追加 `## 易错题` 小节）。可扩展为独立工具：读完一篇 → 生成 3–5 道带答案自测题，追加到笔记末尾，供复习自测。



***

## 4. 第四梯队（P3）・数据资产

### 4.1 一键导出全部笔记（zip）



* 现状：单篇可导出 HTML；全库无整体备份。

* 方案：`GET /api/export` → 打包 `notes/`（含 `.history` 快照可选，排除时可只出当前版）为一个 zip，供本地备份 / 换机迁移。

* 工作量：约 0.5 天。

### 4.2 学习统计仪表盘



* 在仪表盘加一个轻量统计区：笔记总数 / 按类型・标签分布 / 最近 7 天活跃（新增・修改数）/ 复习到期数。纯前端 + 现有 meta 数据即可。



***

## 5. 远期（结合 M8，可选）

### 5.1 MCP 插件化



* README 已把 **M8 团队 / MCP** 列为下一步。把 `fetch_url / fetch_hot / fetch_weather` 等网络工具抽成标准 MCP 服务，好处：


  * 能力与管家解耦，外部 agent / 其他工具可复用；

  * 可按需接入更多外部能力（RSS 订阅源、行业数据、内部知识库）。

* 这是 "从自用工具到可扩展框架" 的跃迁，工作量较大，建议前面的 P0–P2 稳定后再动。
